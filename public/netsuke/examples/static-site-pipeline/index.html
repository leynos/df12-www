Static Site Pipeline

Compile each Markdown page into HTML, then rebuild a shared index from the generated output. This example is small on purpose: it shows `glob`, `foreach`, and a script-backed target without hiding the graph.

Back to Examples Rules & Targets

Directory Structure

site-example/
  • pages/
  • index.md
  • about.md
  • site/
  • Netsukefile

The manifest reads Markdown from pages/, writes HTML into site/, then synthesises an index page from the generated files.

Why it matters

This is the design-doc workflow in miniature: templating resolves first, then Netsuke turns an explicit file graph into Ninja rules.

Annotated Manifest

docs/examples/website.yml 
netsuke_version: "1.0.0"

vars:
  pages_dir: pages
  site_dir: site

rules:
  - name: page
    command: "pandoc {{ ins }} -o {{ outs }}"

  - name: index
    script: |
      cat {{ ins }} > {{ outs }}

targets:
  - foreach: glob(pages_dir ~ '/*.md')
    name: "{{ site_dir }}/{{ item | basename | replace('.md', '.partial.html') }}"
    rule: page
    sources: "{{ item }}"

  - name: "{{ site_dir }}/index.html"
    rule: index
    sources: "{{ glob(site_dir ~ '/*.partial.html') | sorted }}"

defaults:
  - "{{ site_dir }}/index.html"
1

`foreach` expands the page set

The target list comes from `glob(...)`, so each Markdown file becomes one `.partial.html` output without duplicating the rule block.

2

Scripts still live inside the manifest

The `index` rule gathers `glob(site_dir ~ '/*.partial.html')` with a short shell script. Netsuke keeps it in the same graph as the Pandoc step instead of splitting logic across extra wrappers.

3

Defaults name the deployable artefact

Running `netsuke` with no target builds `site/index.html`, not an abstract package target.

Running the Build

Terminal
➜ ~/site-example netsuke build site/index.html
0.0s INFO Parsed `Netsukefile` and expanded page targets from `glob(...)`.
0.1s INFO [1/3] Rendering `pages/about.md` to `site/about.partial.html`
0.1s INFO [2/3] Rendering `pages/index.md` to `site/index.partial.html`
0.2s INFO [3/3] Rebuilding `site/index.html` from `glob(site_dir ~ '/*.partial.html')`
Build complete: site/index.html

Build Flow

1. Discover

Read `pages/*.md` with `glob(...)`.

2. Expand

Create one `page` target per input file.

3. Render

Invoke Pandoc for each Markdown page.

4. Assemble

Concatenate the generated `.partial.html` files into `site/index.html`.
