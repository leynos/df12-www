Batch Photo Processing

Convert a directory of RAW files into JPEG output and then regenerate a gallery page from the resulting images. This example shows how Netsuke fans one rule over many files and still finishes with a single top-level artefact.

Back to Examples Templating Guide

Directory Structure

photo-workflow/
raw_photos/
IMG_1001.CR2
IMG_1002.CR2
processed/
Netsukefile

The manifest treats `raw_photos/*.CR2` as the source set, writes converted JPEGs into `processed/`, then rebuilds `processed/gallery.html` from the output directory.

Why it matters

`glob(...)` is not just a convenience helper. It is how one manifest describes a changing file set and still compiles to a static Ninja graph.

Annotated Manifest

docs/examples/photo_edit.yml 
netsuke_version: "1.0.0"

vars:
  raw_dir: raw_photos
  out_dir: processed

rules:
  - name: convert_raw
    command: "darktable-cli {{ ins }} {{ outs }} --core --width 100% --height 100% --quality 92"
    description: "Converting {{ outs }}"

  - name: make_gallery
    command: "make-gallery {{ out_dir }} > {{ outs }}"

targets:
  - foreach: glob(raw_dir ~ '/*.CR2')
    name: "{{ out_dir }}/{{ item | basename | replace('.CR2', '.jpg') }}"
    rule: convert_raw
    sources: "{{ item }}"

  - name: "{{ out_dir }}/gallery.html"
    rule: make_gallery
    sources: "{{ glob(out_dir ~ '/*.jpg') }}"
    always: true

actions:
  - name: preview
    script: |
      feh {{ out_dir }} &

defaults:
  - "{{ out_dir }}/gallery.html"
1

One target template, many outputs

`foreach` walks every CR2 file and stamps out one JPEG target per input.

2

The gallery target is marked `always`

The HTML page should always refresh when invoked, even if the output file already exists.

3

Actions stay outside the default graph

`preview` is useful, but it is not part of the build product. Actions let the manifest describe both.

Running the Build

Terminal
➜ ~/photo-workflow netsuke build processed/gallery.html
0.0s INFO Expanded 42 RAW inputs from `raw_photos/`.
0.3s INFO [1/43] Converting `IMG_1001.CR2`
2.8s INFO [42/43] Converting `IMG_1042.CR2`
2.9s INFO [43/43] Rebuilding `processed/gallery.html`
Build complete: processed/gallery.html

Build Flow

1. Discover

Find every CR2 file in `raw_photos/`.

2. Convert

Run `darktable-cli` once per source file.

3. Gather

Collect the generated JPEG paths with `glob(...)`.

4. Publish

Write `processed/gallery.html` from the output set.
